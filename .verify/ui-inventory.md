## 3. BRIDGE CONTRACT (window.pywebview.api — from wisper/webui.py `Api`)

All methods are JSON in/out, async from JS (wrapped in Promises). 16 methods:

status/control:
- `get_status()` -> `{ state: "idle"|"recording"|"processing"|"error", last_text: string, last_error: string|null, level: number(0..1) }`  (polled ~200ms; drives every view)
- `toggle()` -> null   (start if idle/error; stop+process if recording — same as hotkey)
- `cancel()` -> null   (abort; also used to dismiss the error view)

devices:
- `list_devices()` -> `string[]`   (labels like `"Pebble Comet Headset — WASAPI"`; UI dedupes with Set)
- `refresh_devices()` -> `string[]`  (rescan, same shape)
- `set_device(name: string)` -> null   (pass the full label OR "" for auto; Python strips the " — HostAPI" suffix itself via `_bare_device_name`)

settings:
- `get_settings()` -> `{ hotkey, input_device: string|null, model, device, compute_type, samplerate: number, language, output_language, cleanup_mode, stt_provider, groq_model, sound_effects: boolean, history_size: number, paste_mode }`
- `get_options()` -> `{ cleanup_modes[], paste_modes[], stt_providers[], groq_models[], languages[], local_models[] }`
- `set_setting(key: string, value)` -> null   (persists immediately; keys: hotkey, stt_provider, groq_model, model routed to app methods; input_device, samplerate, device, compute_type, language, output_language, cleanup_mode, sound_effects, history_size, paste_mode = plain config; unknown keys ignored)

models:
- `models_status()` -> `{ [modelName: string]: boolean }`
- `download_model(name: string)` -> `{ name, downloaded: boolean, path: string|null, error: string|null }`  (blocking; UI polls models_status() while it runs)

history:
- `history_load(size?: number)` -> `[{ ts: string, text: string }, ...]`  (newest-first)
- `history_delete(ts: string, text: string)` -> null   (keys on BOTH fields)
- `history_clear()` -> null

window (frameless chrome):
- `window_minimize()` -> null
- `window_close()` -> null

### Python -> JS events/callbacks
- NONE pushed by Python. No `evaluate_js`, no injected calls, no on_loaded hook.
- Only signal: pywebview's native `window.pywebviewready` DOM event fires when
  `window.pywebview.api` is live. `api.ts::bridgeReady()` listens for it with a
  350ms fallback to the built-in mock (used for browser preview only).

### Boot / handshake sequence
1. pywebview loads dist/index.html -> React mounts (main.tsx -> App).
2. `backend()` returns `window.pywebview.api` if present, else the mock in api.ts.
3. App phases are UI-only: `loading` (LoadingScreen.onDone) -> `landing` (Landing.onStart) -> `app`. NOT gated on the bridge.
4. On entering `app`: `subscribeStatus()` starts the 200ms `get_status()` poll; `get_settings()` is called once to grab `hotkey`. Panels lazy-load settings/options/devices/models on open.
5. Current state is learned ENTIRELY from `get_status()` polling — no push. The view is derived: recording->ActiveView(recording), processing->ActiveView(processing), error->ErrorView, else IdleView. A processing->idle transition with fresh last_text triggers the "Pasted …" toast.

### How pywebview loads the UI + window config (webui.py `launch`)
- URL: `<repo>/dist/index.html` (`_BUILT`) if it exists, else `wisper/web/index.html` (`_INDEX`) as a file:// URI.
- `webview.create_window(title="Say It", width=720, height=720, min_size=(600,600), frameless=True, easy_drag=False, background_color="#0a0c11", js_api=Api)`.
- Frameless: the UI owns its own drag region via CSS `-webkit-app-region` (`.drag`/`.no-drag` classes); min/close handled by `window_minimize/close`. Not transparent, not resizable beyond min.

## 4. FUNCTIONAL CONTROL CHECKLIST (new UI MUST reproduce; -> bridge method)

- Start/stop dictation (button + implicit hotkey parity) -> `toggle()`
- Cancel / abort in-flight -> `cancel()`
- Live status + mic level meter (idle/recording/processing/error, level 0..1) -> `get_status()` poll
- "Pasted …" confirmation toast on processing->idle w/ new text -> derived from `get_status().last_text`
- Show current hotkey (display only) -> `get_settings().hotkey`
- Mic device dropdown (WASAPI labels, Pebble Comet, deduped, "Auto" option) -> `list_devices()` / `set_device()`
- Refresh device list -> `refresh_devices()`
- Spoken language selector (multilingual) -> `set_setting("language", v)` + `get_options().languages`
- Output/translation language selector -> `set_setting("output_language", v)`
- Cleanup mode (light/casual/formal/structured/raw — Groq/reform stack) -> `set_setting("cleanup_mode", v)`
- Transcription provider (groq | local) -> `set_setting("stt_provider", v)`
- Groq model picker -> `set_setting("groq_model", v)` + `get_options().groq_models`
- Local speech model picker + download w/ progress -> `set_setting("model", v)`, `models_status()`, `download_model()`
- Paste mode (auto/ctrl_v/ctrl_shift_v) -> `set_setting("paste_mode", v)`
- Sound effects toggle -> `set_setting("sound_effects", bool)`
- History size / hotkey (display only in settings) -> `get_settings()`
- History list (newest-first), copy (clipboard), delete one, clear all -> `history_load()`, `history_delete(ts,text)`, `history_clear()`
- Window minimize / close (frameless chrome) -> `window_minimize()` / `window_close()`
- Theme light/dark (localStorage "say-it-theme"), mascot/logo position (localStorage "say-it-mascot-pos") -> UI-LOCAL, no bridge (client-side only; optional to reproduce)

## 6. UI-vs-CORE BOUNDARY — AMBIGUITIES TO FLAG

- `wisper/web/**` is an OLD vanilla-JS UI AND the fallback `webui.py` loads when
  `dist/index.html` is absent. It is presentational (delete candidate), but if you
  delete BOTH `dist/` and `wisper/web/`, the app has no UI to load and `launch()`
  points at a nonexistent file. Safe path: keep at least one; after `npm run build`
  produces a fresh `dist/index.html`, `wisper/web/` can go.
- `wisper/ui.py` is legacy tkinter UI (presentational) but reachable via
  `--classic`/`WISPER_UI=classic`. Kept in KEEP; delete only if you also drop the
  classic path in `__main__.py`.
- `src/lib/api.ts` + `src/lib/types.ts` are frontend source but are the canonical
  bridge contract — treat as spec, not disposable UI.
- `webui.py` is the single hard UI<->core seam. As long as the new UI keeps the 16
  method names + payload shapes above and the poll model, core is untouched.
